# Conventions for AI Agents

## House rule

- The maintainer always builds images themselves. Agents analyze and edit — do NOT run `./compile.sh build` or other full builds.

## Build entrypoint

- `./compile.sh <command> KEY=VALUE ...` — single entrypoint; first non-param arg is the command, everything else is `KEY=VALUE` (any order).
- Valid commands are registered in `lib/functions/cli/commands.sh`. There is **no `image` command** — a full image is `./compile.sh build`. Common: `build`, `kernel`, `kernel-config`, `uboot-config`, `kernel-patch`, `docker`, `flash`, `requirements`.
- `./compile.sh requirements` installs host deps (CI runs it first, with sudo).

## Kernel commit pinning (most common task)

- `BRANCH=current` → fork `leftymods/linux-6.18.y`, pinned via `KERNELBRANCH="commit:<sha>"` in `config/sources/families/include/meson64_common.inc` (the `current)` case).
- To bump: `git ls-remote https://github.com/leftymods/linux-6.18.y.git main` → update the SHA in that file.
- Custom kernel sources (not `kernel.org`/`googlesource.com`) bypass ORAS bundles and are shallow-cloned directly — logic in `lib/functions/compilation/kernel-git-oras.sh` ("Custom kernel source detected").

## Auto-generated files — DO NOT edit

- `lib/library-functions.sh` — regenerate with `lib/tools/gen-library.sh`.
- `Dockerfile` — generated by `./compile.sh docker` (`generate-dockerfile`); not committed.

## Deprecated workflows (no `KERNEL_CONFIGURE=yes` etc.)

Use the dedicated commands instead:
- `./compile.sh kernel-config BOARD=... BRANCH=...` (not `KERNEL_CONFIGURE=yes`)
- `./compile.sh uboot-config BOARD=... BRANCH=...` (not `UBOOT_CONFIGURE=yes`)
- `./compile.sh kernel-patch BOARD=... BRANCH=...` (not `CREATE_PATCHES=yes`)

## Patches policy

- All board-specific changes go directly into the kernel fork (`leftymods/linux-6.18.y`), NOT as patch files.
- **ALL kernel patch files** in `patch/kernel/archive/meson64-*` are disabled (`.patch.disabled`, zero enabled). Never enable them.
- **ALL rtl8723cs staging driver patches** are skipped on `meson64` (early return in `driver_rtl8723cs()` in `lib/functions/compilation/patch/drivers_network.sh`).
- Only exception: Armbian's built-in DT/overlay auto-patching is OK (part of the build pipeline, not patch files).
- When touching `patch/`, stage specific files only — never `git add` the whole directory (huge; accidental commits have happened).

## Board & architecture

- **One board**: `atristation` (`config/boards/atristation.conf`) — Amlogic S905X3, `meson-sm1` family. Hardware is a Yandex Station 2 smart speaker; AtriOS replaces its cloud stack with an offline one.
- Board enables custom extensions in `extensions/`: `rotary-poll` (GPIO volume knob polling), `atrisound` (SY6045S amps + UCM), `atri-main` (offline daemon replacing Yandex `maind`: SPI LED matrix, IS31FL3236 ring LEDs, input events). Custom packages in `packages/`: `atri-led`, `atri-main`, `quasar-led-screen`, `plymouth-theme-atrios`.
- WiFi/BT is RTL8822CS (rtw88 + serdev hci_h5); BT firmware loads via kernel driver, no hciattach needed.

## Dependencies & lint

- Python tools pinned in `requirements.txt` (fixed versions, Dependabot-owned; add a purpose comment for new entries).
- Pre-commit hooks: gitleaks, shellcheck, cpplint, pylint, end-of-file-fixer, trailing-whitespace.
- Workspace path must not contain whitespace (`compile.sh` aborts).
- Pinned tool versions in `lib/*.sh` (`SHELLFMT`/`SHELLCHECK`/`ORAS`/`BATCAT`) are Renovate-tracked. The exact required line format is documented in the big comment at the top of `renovate.json5` — break it and Renovate silently drops tracking.

## CI

- Main build: `.github/workflows/build-atrios.yml` → composite action in root `action.yml`. The action auto-bumps the patch component of `VERSION` and publishes a GitHub release. (`target` must be a real `compile.sh` command — `build` or `kernel`; the workflow's `image` default is not one.)
- Docker image: `.github/workflows/build-docker.yml` — pushed on `Dockerfile`/`requirements.txt` changes to main.
- Kernel ORAS bundle: `.github/workflows/build-oras.yml` — weekly and manual dispatch.
